API Reference

The documented names of ArkModelZoo.jl. Each model also exports its parameter type (XParams) and runner (run_x); the model pages show how to use them.

ArkModelZoo.AbstractArkProblem — Type
AbstractArkProblem <: SciMLBase.AbstractSciMLProblem

Supertype of the ArkModelZoo models wrapped as SciML problems: DaisyworldProblem and WolfSheepProblem. Solve one with solve(prob, TickStepping()), step one with init/step!, or run many with EnsembleProblem.

source
ArkModelZoo.ArkIntegrator — Type
ArkIntegrator

The integrator returned by init(prob::AbstractArkProblem, TickStepping()). It implements the part of SciML's integrator interface that simulation-based metrics use:

  • integ.u: the summary vector of the current world; integ.t: the tick; integ.p: the parameters, which may be reassigned (integ.p = q) to change them from the next tick on, for example to ramp a forcing;
  • step!(integ) (one tick) and step!(integ, dt, stop_at_tdt = true) (dt whole ticks);
  • reinit!(integ): rebuild the world from the problem and replay exactly, the random streams included;
  • set_u!(integ, u), or mutate integ.u and call derivative_discontinuity!(integ, true): move the world to the summary u (see the problem's docstring for how);
  • terminate!, check_error, solve!.
source
ArkModelZoo.ArkSolution — Type
ArkSolution

The result of solve(prob::AbstractArkProblem, TickStepping()): the saved summaries u, their ticks t, and a retcode. sol.u[end] is the final summary.

source
ArkModelZoo.DaisyworldProblem — Type
DaisyworldProblem(params = DaisyworldParams(); u0 = nothing, tspan = (0, params.max_ticks),
                  seed = params.seed)

Daisyworld as a SciML problem, advanced by TickStepping.

The state is the summary u = [T, w, b]: T the mean temperature of the grid, w and b the fractions of cells holding a white and a black daisy.

  • u0 = nothing starts from the model's own random initial state (start_pct_whites and start_pct_blacks of the cells planted). A vector u0 is then imposed on that state as set_u! would; an entry NaN leaves that component as initialised.
  • Setting a summary (set_u!, u0, or a perturbation in recovery) moves the world by the smallest random change with that summary. Every cell's temperature is shifted by the same amount, so the spatial pattern is kept. Daisies of a colour are removed at random, or planted at random empty cells with ages drawn uniformly from 0:max_age as at initialisation. Cover is rounded to whole cells, so integ.u after the change is the summary actually reached. These random choices use a stream kept apart from the model's, so a perturbation does not itself shift the model's random numbers (the streams still diverge afterwards, because the model draws one number per daisy).
  • integ.p = q changes the parameters from the next tick on; solar_luminosity takes effect at once (unless ramp_scenario is set, in which case the model ramps it itself). grid_size cannot change.

The model's own stopping rule (max_ticks) is ignored: tspan sets the length of a run.

ArkModelZoo.WolfSheepProblem — Type
WolfSheepProblem(params = WolfSheepParams(); u0 = nothing, tspan = (0, params.max_ticks),
                 seed = params.seed)

Wolf–Sheep predation as a SciML problem, advanced by TickStepping.

The state is the summary u = [S, W, G]: the numbers of sheep, of wolves and of green grass patches (G = 0 when grass is disabled).

  • u0 = nothing starts from the model's own random initial state. A vector u0 is then imposed on that state as set_u! would; an entry NaN leaves that component as initialised.

  • Setting a summary (set_u!, u0, or a perturbation in recovery) moves the world by the smallest random change with that summary:

    • animals are removed at random, or added as at initialisation: a uniform random position, a random heading, and energy drawn from 0:9;
    • grass patches are turned brown (countdown drawn from 1:grass_regrowth_time) or green, at random.

    Counts are rounded to whole animals and patches. The random choices use a stream kept apart from the model's, so a perturbation does not itself shift the model's random numbers (the streams diverge afterwards, because the model draws numbers per animal).

  • integ.p = q changes the parameters from the next tick on; the grid size cannot change.

The model's own stopping rules (both species extinct, max_ticks) are ignored: tspan sets the length of a run, and the grass keeps growing after the animals are gone.
