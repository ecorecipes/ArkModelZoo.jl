ArkModelZoo.jl

A collection of classic agent-based models ported from NetLogo to Julia using the Ark.jl Entity Component System (ECS) framework.

Models

ModelOriginPatternDescription
SegregationSchelling (1971)Spatial preferenceAgents move until local neighborhood meets similarity threshold
Wolf-Sheep PredationWilensky (1997)Multi-breed predator-preyWolves eat sheep, sheep eat grass, with energy and reproduction
AntsWilensky (1997)Stigmergy / pheromone trailsAnts forage for food using chemical trail communication
DaisyworldWatson & Lovelock (1983)Ecology feedbackBlack and white daisies regulate planetary temperature
VirusWilensky (1998)Spatial epidemiologySIR disease model with movement, aging, and reproduction
EthnocentrismHammond & Axelrod (2006)Evolutionary game theoryIn-group/out-group cooperation strategies evolve via selection

Quick Start

using ArkModelZoo

# Run Schelling's Segregation model
scheduler, trajectory = run_segregation(
    params = SegregationParams(density=80.0, pct_similar_wanted=30.0)
)

# Run Wolf-Sheep Predation
scheduler, trajectory = run_wolfsheep(
    params = WolfSheepParams(initial_number_sheep=100, initial_number_wolves=50)
)

# Run Ants
scheduler, trajectory = run_ants(params = AntsParams(population=125))

# Run Daisyworld
scheduler, trajectory = run_daisyworld(params = DaisyworldParams(solar_luminosity=0.8))

# Run Virus (SIR with movement)
scheduler, trajectory = run_virus(params = VirusParams(number_people=200, virus_spread_chance=0.15))

# Run Ethnocentrism
scheduler, trajectory = run_ethnocentrism(params = EthnocentrismParams(max_ticks=2000))

To see the full catalog of available model entry points:

using ArkModelZoo

available_models()

For richer discovery metadata:

using ArkModelZoo

model_categories()
model_catalog(category="Biology & Ecology")
model_info("run_rgw")
model_info("simple_birth_rates")
run_model("simple_birth_rates"; params = BirthRatesParams(max_ticks=25))

You can also inspect the exported run functions directly:

sort(filter(name -> startswith(String(name), "run_"), names(ArkModelZoo)))

NetLogo-style wrapper spellings such as simple_birth_rates, disinfo_nw_bitstring, artificial_economy, and search_path resolve through model_info and the generic run_model entry point.

Resilience: SciML problems

Daisyworld and Wolf–Sheep can also be run as SciML problems, DaisyworldProblem and WolfSheepProblem, advanced one tick at a time by TickStepping(). Their integrators provide init, step!, reinit! (an exact replay), set_u!, solve and EnsembleProblem. So the simulation-based resilience metrics of DynamicalResilience.jl, re-exported here, run on them directly: recovery, basin_stability, ramped_series and early_warning.

using ArkModelZoo
prob = DaisyworldProblem(DaisyworldParams(solar_luminosity = 1.8); u0 = [NaN, 0.2, 0.2], tspan = (0, 300))
basin_stability(prob, TickStepping(); trajectories = 100, seed = 1,
                sample_perturbation = (u, rng) -> [NaN, 0.5rand(rng), 0.5rand(rng)],
                returned = u -> u[2] + u[3] > 0.05)

The state is a summary vector:

  • Daisyworld: [mean temperature, white cover, black cover];
  • Wolf–Sheep: [sheep, wolves, green patches].

Setting it moves the world by the smallest random change with that summary. The vignette vignettes/resilience/resilience.qmd covers:

  • basin stability and early-warning indicators for Daisyworld;
  • return after a pulse, and coexistence basins, for Wolf–Sheep.

step! is SciML's step!, so step!(scheduler) and step!(integrator, dt, true) are the same function.

ECS Architecture

Each model follows the same ECS pattern:

  • Components: Lightweight mutable structs attached to entities (position, energy, health state, etc.)
  • Resources: Global singleton state (grids, statistics, parameters, RNG)
  • Systems: Ordered pipeline of update functions (initialize!, update!, finalize!)
  • Scheduler: Runs systems in deterministic order, manages tick counter and termination
World ─┬─ Components (per-entity data)
       ├─ Resources (global state)
       └─ Systems (ordered update pipeline)

Installation

using Pkg

# Install from a checkout
Pkg.develop(path="path/to/ArkModelZoo.jl")

# Or install directly from GitHub
Pkg.add(url="https://github.com/sdwfrost/ArkModelZoo.jl")

Requires Ark.jl v0.4+.

Optional Dependencies

  • Shapefile-backed GIS models such as run_diffusionofhiv require Shapefile.jl:

    using Pkg
Pkg.add("Shapefile")

  • Vignette plot pre-rendering uses the separate vignettes/ environment:

    julia --project=vignettes -e 'using Pkg; Pkg.instantiate()'
julia --project=vignettes vignettes/prerender.jl

Testing

using Pkg
Pkg.test("ArkModelZoo")

Some GIS fixture tests depend on external NetLogo ClassModels data. Set NETLOGO_CLASSMODELS_DIR to enable those tests in addition to the default suite.

GitHub Actions includes:

  • .github/workflows/ci.yml for the portable default suite
  • .github/workflows/external-validation.yml for manual GIS fixture and NetLogo calibration runs on a runner that already has the required paths available
